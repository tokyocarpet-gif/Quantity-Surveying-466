# 積算管理 開発仕様

作成日: 2026-09-09

## 1. 本資料の位置付け

本資料は「積算管理」の新規開発仕様であり、実装済み機能や検証合格の報告ではない。

参考資料は、ユーザー指定の `GITHUB_SPEC_PROMPT_2026-09-08.md`。同資料はHIROI Studioの基準コミット `366ecaf7b77cff238c2f24a741770c89a6091c04` の現行仕様整理であり、積算管理の実装コードではない。参考資料内の開発指示は、今回のユーザー指示と採用済み改善方針に照らして扱う。

参考資料に記載された現行動作と、本資料の改善内容が異なる場合は本資料を優先する。旧アプリの制約を互換性要件として引き継がない。

## 2. ユーザーとの確定事項

- アプリ名は「積算管理」。既存アプリの改名・更新ではなく、新規に作成する。
- GitHubリポジトリは `https://github.com/tokyocarpet-gif/Quantity-Surveying-466.git`。
- 利用対象はWindows。開発はWindowsとmacOSの両方で行う。
- 旧アプリのGitHubリポジトリ、履歴、保存データと分離する。
- 数量・金額計算の統一、変更時の再計算、部屋IDによる識別、控除の構造化、見積経路の整理、バックアップと復元、ツール整理の改善案を採用する。
- 実装に先立ち仕様を整理する。本資料作成時点ではアプリ本体を実装していない。

以下の具体的な識別子、対象CPU、丸め方式、操作名称などは採用方針を具体化した初期設計案であり、ユーザーが個別指定した値とは区別する。

## 4. 技術構成と責務

- Electron / React / TypeScript / electron-viteを基本構成とする。
- React RouterのHashRouter、Zustand、SQLite / Prisma、PDF.jsを基本候補とする。
- ExcelはExcelJS、PDF帳票は日本語フォントを埋め込み可能な方式を採用する。具体的なPDFライブラリは帳票の試作で選定する。
- 参考資料のバージョン番号をそのまま固定せず、実装開始時に公式情報で互換性・サポート状況を確認し、Node.jsと依存パッケージをロックファイルで固定する。
- ファイル・DB処理はmain、公開APIはpreload、画面処理はrendererに分離する。
- rendererのNode.js直接利用を無効化し、contextIsolationを有効にする。IPCでは入力型・値・対象データを検証し、任意のファイル操作を公開しない。
- 数量計算をUIに依存しない共通モジュールへ集約し、集計・見積・帳票が同じ計算結果を参照する。
- Windows / macOSで同じnpmスクリプトを使用し、シェル固有のコピー・削除コマンドへの依存を避ける。
- CIはWindows / macOSで型検査・数量計算テスト・ビルドを行う。Windows配布物はWindows上でネイティブ依存を含めて生成し、インストールと起動を確認する。

## 5. 機能範囲と導線

最終的な対象範囲は、顧客・案件・図面管理、PDF拾い出し、集計、保存型見積、Excel / CSV / PDF出力、床材割付、CADとする。段階的に実装し、未完成の機能を利用可能と表示しない。

基本導線は「顧客 → 案件 → 図面 → 縮尺設定 → 部屋・数量登録 → 集計 → 見積保存 → 帳票出力」。

拾い出しは上部にツールバー、左に部屋一覧、中央に図面、右に属性入力を配置する。左右パネルは折りたたみ可能、部屋一覧は独立スクロール可能とする。部屋内の表示順は天井・壁・巾木・床。

同じ動作を持つ「面積／多角」「部屋／一括拾い」はそれぞれ一つへ整理する。「部屋」の確定後に4部位すべて、または選択した部位を登録する。矩形は描画モードとして明示する。

「壁面を直接測る」と「外周から壁面積を求める」は計算方式として区別して表示する。縮尺未設定、保存中、保存失敗、再計算が必要な状態を画面から判断できるようにする。

初期の図面取り込みはPDFを対象とする。画像対応はPDFと共通の論理座標を設計し、画像上での計測まで検証してから追加する。

## 6. 座標・縮尺・数量

- 図面のページごとに論理座標・縮尺・回転を管理する。ズームや表示密度の変更で数量が変わらないようにする。
- 縮尺は論理座標の1単位あたりのmとして保持し、縮尺なしの図形は未計測扱いにする。pxやpx²を実寸として集計しない。
- 壁高さ・開口寸法の入力はmm、実数量はm / ㎡ / 個。計算方式と単位は別に保持する。
- ポリゴン面積、閉じた外周長、折れ線長さ、点数を基礎量として計算する。
- 部屋の自動数量は天井=面積、壁=外周×高さ、巾木=外周、床=面積。
- 壁面直接計測は描いた面積を採用する。同時登録の壁は外周×高さを採用する。
- 壁高さの初期値案は2400mm。0以下・非有限値を拒否する。自己交差・退化したポリゴンはエラーとして修正を促す。
- 手入力数量と図形由来の数量を識別し、計算方式、参照図形、縮尺、使用高さ、計算バージョンを追跡できるようにする。

縮尺・高さ・ポリゴン変更時は対象明細と変更前後の数量をプレビューする。確認後に数量と関連金額を一括更新する。手入力で固定した数量は自動上書きせず、対象があることを表示する。キャンセル時は元の値を維持する。

## 7. 部屋・控除・資材

- 部屋の関連付けは `roomId` を基準とし、部屋名は表示情報とする。同名の部屋は既定で独立したIDを保持する。ユーザーの明示選択で同一ページ内の範囲をグループ化し、数量を合算できる。
- 部屋の所属図面・ページを保持し、名称変更で関連付けが失われないようにする。
- 部屋更新と自動明細更新はDBトランザクションで行う。控除の参照先が失われないよう、自動明細は可能な限り安定したIDで更新する。
- 手動明細は自動明細と区別する。部屋削除時は影響を示し、自動明細を削除、手動明細は部屋参照を外して保持する。
- 控除は対象明細ID・控除種別・寸法・数量を専用データとして保存する。メモの特殊文字列を計算根拠にしない。
- 開口控除は幅×高さによる面積を扱い、対象部位の単位と一致することを検証する。巾木の長さ控除は面積控除と別に扱う。
- アクセント壁は通常壁からの控除とアクセント仕上げ明細を関連付け、二重控除を防ぐ。
- 控除対象を削除する場合は依存する控除も対象として明示し、孤立した参照を残さない。
- 正味数量が負になった場合は過大控除として表示する。自動で0へ補正せず、該当項目が解決するまで正式見積の確定を止める。
- 共通の仕上げ材マスタから物件用マスタへ必要な材料を一括コピーし、拾い時に部位別リストで選択する。共通・物件ごとに名称と単価を編集できる。資材・仕様・単位・標準単価の管理を統一する。案件明細・見積には採用時の値を保存し、マスタ変更で既存の見積金額が変わらないようにする。

## 8. 集計・見積・帳票の整合性

2026-09-11のユーザー指定：集計の数量表示と見積の数量表示は小数1桁。見積では採用数量も小数1桁へ四捨五入し、金額計算に使用する。幾何計算の保存精度は保持する。この指定は以下の初期案の桁数に優先する。v0.6.0で保存型見積へ実装済み。

共通の計算結果に「元数量」「控除数量」「正味数量」「単位」「単価」「金額」を持たせる。集計・見積生成・帳票は同じ計算条件を使用する。

丸めの初期案は、幾何計算の途中では丸めず、数量表示と見積採用数量の精度を区別して保存する方式とする。見積は採用数量×単価から明細金額を計算し、円単位の丸め方式、税率、税計算のタイミングを見積ごとの設定として固定する。表示値と金額の検算が一致するよう、出力にも採用数量を使用する。既定の桁数・丸め方式は見積機能実装前に具体例で確定する。

集計は部屋×仕上・仕上別・部屋別・図面別の4表示を基本とする。絞り込み条件と集計対象範囲を明示し、出力には同じ条件を適用する。

見積は保存型へ統一する。集計から下書きを作成し、部屋・明細・順序・単価・表紙情報を編集して保存・出力する。下書き編集で元の拾いデータを書き換えない。

- 集約キーには部位・資材・仕様・単位・単価などを含める。異なる単価を単純平均で混ぜず、単価別の明細にする。
- 見積生成時の元明細と計算条件を記録する。
- 再生成で保存済み見積を無条件に上書きしない。新しい版を作成し、旧版を残す。
- 未入力単価は0円と区別し、確認対象として表示する。
- CSVも正味数量を含む共通結果を通常出力とする。生データ出力が必要な場合は別の出力種別として明示する。
- PDF / Excelは日本語、改ページ、長い名称、数量・単価の表示精度を検証する。

## 9. 保存・バックアップ・復元

- 保存失敗を成功表示にしない。再試行できるよう編集内容を保持する。
- バックアップはDB・管理図面・設定・形式バージョンを含む、一貫した状態のパッケージとする。SQLiteの稼働中ファイルを単純コピーしない。
- 復元前に形式、必要ファイル、整合性を検証し、現在のデータも退避する。復元失敗時は元に戻せるようにする。
- WindowsとmacOSの間でバックアップを移して復元できることを検証する。同一DBのネットワークドライブ共有運用は想定しない。
- スキーマ変更には積算管理自身のバックアップと移行手順を用意する。
- 顧客・案件・図面削除で影響する部屋、数量、割付を列挙し、参照とファイルの残存方針を定義する。

## 10. 床材割付・CAD・追加機能

床材割付とCADの機能範囲は参考資料を出発点にするが、独立した工程で仕様を具体化する。

- 割付への部屋取り込みは名前で重複判定せず、元の部屋ID・図面・ページを参照する。
- 拾い出しのm座標と割付・CADのmm座標の変換を共通化する。
- タイルはパターン、端材、ロス、ケース入数の計算条件を保存する。
- シートの必要長さとPDFサマリーも検証対象とし、未対応部分は画面で明示する。
- 巾木本数は固定900mmだけにせず製品長を設定できる設計とする。開口控除後の長さを使うかを明示する。
- CADの部屋連携は選択中の図面ページを使用し、ページ1へ固定しない。
- 汎用Undo / Redoは別途コマンド履歴と永続化の範囲を設計する。削除取り消しだけの段階で全面対応と表示しない。
- AI拾い、DWG / DXF、クラウド同期は初期範囲外とする。

## 12. 主要な受入検証

1. 「積算管理」の名称で起動し、旧アプリとは別の領域へ保存する。
2. Windows / macOSで顧客・案件作成、PDF取り込み、保存・再起動を確認する。
3. 4m×3m・高さ2400mmの部屋が、天井12㎡、壁33.6㎡、巾木14m、床12㎡になる。
4. 同じポリゴンを壁面として直接登録すると12㎡となり、外周由来の壁33.6㎡と区別される。
5. 壁高さを3000mmへ変更する再計算では壁が42㎡となり、床・天井・巾木は変わらない。
6. 同じ形状の縮尺を2倍にしたとき、面積は4倍、長さは2倍、高さ一定の外周由来壁面積は2倍になる。
7. 900mm×2000mmの開口を壁33.6㎡から控除すると正味31.8㎡になる。
8. 縮尺未設定、過大控除、無効な図形・数値、単位不一致が正式な数量や見積へ混入しない。
9. 同じページ・別ページ・別図面の同名部屋が混ざらず、名称変更でも参照が維持される。
10. 部屋更新で自動明細と控除の参照が維持され、手動明細が失われない。途中失敗時は全体をロールバックする。
11. 異なる単価の明細が別に生成され、未入力単価と0円が区別される。
12. 同じ条件の集計・見積生成・CSV・Excel・PDFが、数量・控除・金額について一致する。
13. 見積下書きの編集と再生成で元の拾いと旧見積版が失われない。
14. バックアップを別環境へ復元し、図面、部屋、数量、設定が一致する。破損バックアップで現在のデータが壊れない。
15. 日本語・空白を含むパス、大きなPDF、複数ページ、回転ページ、多数の部屋を確認する。性能の数値目標は検証用PDFを決めてから設定する。
16. 型検査・計算テスト・ビルドに加え、Windowsで配布物のインストールと主要操作を確認する。macOSでの成功のみをWindows合格としない。

## 2026-09-10 操作改善の追加要件

- ホイールズームはカーソルを中心とし、右ドラッグでパン。描画中はクリックとドラッグを区別する。
- 多角形では水平・垂直の自動補助を標準動作とし、軸に近づくと吸着、離すと斜め描画へ戻る。切替チェックは設けない。十字線は図面表示領域全体へ伸ばす。マウスのボタン操作・始点クリックで描画を確定できる。
- 部屋名は物件内の過去の採用履歴から選択できる。
- 数量確認は今回の変更対象に絞り、関係ない部屋を表示しない。縮尺変更時は影響する部屋を表示する。
- 同名統合は保存前に選択・合計確認する。形状や共通辺の重複は自動除去しない。範囲ごとの属性・控除・固定数量を保持し、削除・編集できる。
- 複数ページPDFは一つのファイルとして取り込み、ページリストから移動する。縮尺・拾いはページ単位で保存し、異なるページを自動で統合しない。
- 床材割付の実装時にも、ズーム・パン・マウスによる確定操作を共通利用する。

## 2026-09-10 高さ・袖壁・縮尺表示の追加要件

- 新規部屋には物件内の前回確定高さを引き継ぎ、履歴から選択できる。編集中・確認中の値は履歴に含めない。
- 厚みのない袖壁は部屋外周とは別の2点線で保存し、片面／両面・高さ・巾木を指定して加算する。外周の自己交差を無条件に許可しない。
- 校正した実寸からPDF原寸基準の縮尺を求め、「約1/○○」を表示する。ズーム倍率の影響を受けない。

- 設定・データ管理に自社情報登録を追加し、新規見積の発行者へ反映する。
- 見積の仕上げ・明細名と数量の間に仕様・規格列を置く。材料・拾い・集計・CSV・見積の保存に含める。
- 現行運用に合わせ、消費税と税率設定を表示せず明細合計を示す。この指定は初期の税表示案に優先する。旧見積の税設定は内部の履歴として保持する。
- 仕上げ材マスタで任意の部位・単位を追加し、材料ごとの仕様・規格を保存できる。物件マスタと見積選択に対応する。自動拾いは従来の4部位と面積・長さの単位を使用する。

## 2026-09-12 削除確認・個数拾い

見積の明細削除は対象内容を表示して確認し、不意の削除を防ぐ。図面の個数拾いでは柱型・ルーバーなどにクリックでマークを置き、個・本・箇所などで計数する。縮尺なしでも登録でき、点の追加・取り消し・属性の編集と、個数全体の削除確認を備える。位置と個数をページごとに保存し、単位を区別して集計・見積・バックアップへ引き継ぐ。
